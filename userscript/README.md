# FX Pulse Hover（油猴调试版）

页面上的金额，鼠标停一下就在光标处显示简要换算和汇率。只读、不改页面、30 分钟复用缓存、无账号、无后端。当前 UI 为报纸风：脚本只在命中金额时读取当前位置的网页背景色，自动选用纸色、深色、海蓝、鼠尾草绿或陶土色主题。

这是 [FX-Pulses](https://github.com/shianjeng/FX-Pulses) 的形态实验：把"打开插件查汇率"改成"汇率出现在金额所在的位置"。
当前仍是验证误判率的调试版，因此保留完整的调试 API 和自检页；v0.3 同时完成了可日常阅读的悬停卡片。

## 安装

1. 装 Tampermonkey。
2. 打开 Tampermonkey → 添加新脚本 → 把 `fx-pulse-hover.user.js` 全文粘进去（或把文件拖进浏览器）。
3. **测试本地页面必须**：`chrome://extensions` → Tampermonkey → 详情 → 打开「允许访问文件网址」，否则 `file://` 上的自检页不会注入。
4. 打开 `test-page.html` → 悬停虚线框里的金额。

安装文件始终是 `fx-pulse-hover.user.js` 一份；主题 CSS 和装饰图已经内嵌。要改主题源文件，请先运行 `node embed-theme.mjs`，再重新安装脚本。设置面板中的「自定义主题 CSS」会覆盖内置主题。

### 当前 UI 与取色

卡片以报纸排版组织主换算额、原价、单位汇率、时间与警告。详细模式保留多币种列表、识别证据和操作按钮。取色只发生在悬停命中后，读取金额元素向上最近的不透明 CSS 背景；深色使用 ink，蓝青色使用 marine，绿色使用 sage，红橙紫色使用 clay，中性浅色和无法读取的背景使用 paper。五组具体 token 见 `tokens.md`。图像由 GPT-Image 生成，提示词为：*vintage financial newspaper engraving, a hatched globe with exchange arrows, monochrome dark sepia ink, transparent background, no text or logos*。

## 排障：页面提示「没有检测到 window.__fxph」

**先把两种完全不同的情况分开**。自检页顶部的诊断面板给出 4 个独立信号，看它怎么说：

| ① `#fxph-host` | ② `dataset.fxph` | ③ `window.__fxph` | 结论 |
| --- | --- | --- | --- |
| ✓ | ✓ | ✗ | **不是故障**：脚本在跑，只是油猴沙箱没把 API 桥接给页面（TM 常见）。悬停和自检按钮都正常，只有页面 console 里不能敲 `__fxph` |
| ✓ | ✓ | ✓ | 一切正常 |
| ✗ | ✗ | ✗ | 脚本根本没注入本页 → 按下面清单查 |
| 任意 | 任意 | 任意，但 ④ 有红字 | 脚本注入了但初始化抛错 → 看 console 的 `[FXPH] 初始化失败` |

最快的独立验证：**鼠标停在虚线框金额上 0.3 秒**，弹小窗就说明脚本活着（此时 ①② 必然为 ✓，问题只是桥接）。

脚本没注入时的检查清单（按命中率排序）：

1. `chrome://extensions` → Tampermonkey → 详情 → **「允许访问文件网址」必须打开** —— `file://` 页面被拦下来的头号原因。
2. 脚本头 `// ==UserScript==` 必须在文件**第一行第一字节**：前面不能有空行、空格或 BOM，否则整段元数据失效，`@match` 不生效。
3. 脚本里有 `@match file:///*`（或 `@include file://*`）。
4. Tampermonkey 里该脚本处于「已启用」（不是草稿、不是禁用）。
5. 随便打开一个真实网站：如果那里能弹窗、只有本页不行，就是纯粹的 file:// 权限问题。

**不想折腾 file:// 权限**：点自检页上的「以普通页面脚本加载」，它会用 `<script src>` 把脚本当普通页面脚本注入（GM_* 全部走 localStorage + fetch 降级），识别与小窗行为一致，足以验证核心逻辑；`smoke.html` 也是这个模式。

诊断面板的「复制诊断信息」会把 URL / UA / 三个信号 / 已加载脚本列表复制到剪贴板，贴出来就能定位。

## 两种显示模式 + 设置面板

**简单模式（默认）**：换算金额（主数字）+ **两个下拉常驻**（目标币种 / 原始币种，随时可校准）+ 原始金额 + 单位汇率 + 一行时间戳。**没有复制按钮**——右键点卡片即复制（设置里可关）。

**详细模式**：原始金额大字 + 最多 4 个币种同时换算 + 汇率行 + 完整时间戳（数据时间 / 抓取时间 / 数据源 / TTL）+ 识别证据（可开关）+ 解析细节 + 按钮行；窗口更宽（460px 档）。

**设置面板**（油猴菜单「设置面板」、自检页按钮、或 `__fxph.settings()`）：
显示模式 / 悬停触发时间 80–600ms / 窗口大小 小中大 / 默认目标货币 / 详细模式显示哪些货币 / 汇率缓存 TTL / 右键复制开关 / 显示识别证据 / 在本站禁用 / **本域名校准记忆**（列出并一键清除）/ **自定义主题 CSS**（外包接口）/ 恢复默认 / 复制诊断信息。

配置存在 `GM_setValue`（无油猴时回落 `localStorage`）。两类按域名记忆：`域名|标记 → 币种`（原始币种校准）与 `域名 → 目标币种`。

## 币种识别：证据加权（v0.2 重点）

不再是 if-else，而是给每个候选币种累加独立证据、取最高分，并把证据链显示出来（详细模式 + `__fxph.explain()`）：

| 证据类型 | 例子 | 强度 |
| --- | --- | --- |
| 文字体系比重（整页） | 假名占比 ≥1% → JPY +6；≥0.3% → +4；只出现 1 个 → +2；谚文 ≥0.5% → KRW +6 | 最强 |
| 全文货币标记普查 | 全文「円」8 次 → JPY；「元」12 次 → CNY（数字相邻满分，裸标记 0.4 倍） | 强 |
| 语言标注 | `lang=ja` → JPY +4；`zh-TW` → TWD +4 / CNY +1 | 强 |
| 域名 | `.jp` → JPY +5，`.cn` `.tw` `.kr` `.se` `.ca` `.au`… | 强 |
| 邻近前后文（±60 字） | 紧邻「税込/送料無料」→ JPY +2/个；「含税/包邮」→ CNY +2/个 | 中 |
| 页面关键词 | 全文「税込」等的出现处数 → JPY（上限 +4） | 中 |
| 标记自身先验 | `$` 默认 USD +2；无倾向标记的默认候选 +0.6 | 弱（用于平局） |
| 站点记忆 | 你手动校准过 | 决定性，直接短路 |

置信度 = 最高分与次高分之差映射到 0.4–0.98。置信度**只影响配色与「猜测」徽章**（`< 0.85` 进 `ambiguous` 状态、`< 0.7` 打徽章）；**两个下拉与置信度无关，始终都在**——卡片结构因此稳定，用户任何时候都能校准，而不是"系统不确定时才给你改的机会"。

`node node-check.mjs` 里每条都有对应用例，例如：

- 日本站点把 `lang` 写错成 `zh-CN`，但正文假名占 2% → 仍判 JPY（文字体系压过语言标注）
- 中文页里出现 1 个假名（品牌名）→ 不翻盘，仍 CNY 但降为「猜测」
- 无语言无域名，但全文「円」出现 8 次 → JPY
- 台湾站点写「1,000元」→ TWD（`lang=zh-TW` + `.tw` + 全文有 `NT$`）
- `.ca` 站点的 `$` → CAD（域名 5 分 > USD 先验 2 分）
- 北欧 `1 299 kr` → 按 `.se` / `.no` / `.dk` 分别判 SEK / NOK / DKK

## 三种调试方式

**① 自检页（不碰真实站点）**
打开 `test-page.html`，点「运行解析自检」：74 条用例逐条比对，同一套用例 node 里也跑得通，所以"解析逻辑错了"和"浏览器环境有问题"能分开定位。悬停虚线框则走真实的 `caretRangeFromPoint` + 矩形守卫路径。

**② 真实站点（这才是关键）**
建议按这个顺序走，每个站点悬停 20 个金额，然后点「打印统计」：

```
Amazon.com（$）→ Amazon.co.jp（￥/円）→ 楽天（円）→ 淘宝/京东（¥/元/万）
→ Booking（€/$）→ 一个中文新闻站（裸数字/年份密集）→ 一个 GitHub 页面（代码块）
```

**③ 控制台 / 油猴菜单**

```js
__fxph.stats.dump()                    // 本次会话：扫了多少次、命中多少次、每条拒绝原因各多少次
__fxph.scan()                          // 整页扫描，输出所有识别到的金额（不看悬停，直接看识别面）
__fxph.parseAll('¥1,000', {lang:'ja', host:'x.jp'})   // 单条文本试解析，带拒绝原因
__fxph.rates()                         // 当前用的汇率表、来源、新鲜度
__fxph.refresh()                       // 忽略缓存重新拉
__fxph.cfg                             // 当前配置（显示模式、目标币种、TTL、站点黑名单、校准记忆）
__fxph.explain('¥1,000')               // 单条文本：解析结果 + 逐条证据（含分数与落选候选）
__fxph.profile()                       // 当前页面画像：假名/汉字/谚文占比、全文货币标记普查、语言
__fxph.settings()                      // 打开设置面板
__fxph.setTheme(':host{--fxph-accent:#ffb703}')   // 直接替换主题 CSS（外包设计接入口）
__fxph.set('mode', 'detail')            // 改任意配置项并保存
```

油猴菜单里还有：调试日志开关、刷新汇率、切换目标币种、**在本站禁用**、清空本站币种记忆。

## 设计取舍

**只在光标真的落在金额上时才弹。** 三重条件：悬停静置 180ms → 光标下文本节点里有金额 → 该金额的矩形框覆盖光标（±6px）。漏识别可以接受，误弹窗不可接受。

**必须出现货币标记才认。** `¥ $ € USD 元 円 万...` 缺一不可。裸数字（年份、评分、分辨率、电话、期数、库存量）一律不识别——单独这一条规则就消灭了绝大部分误判。代价是 `1,299` 这种无符号金额永远不认，以后只能靠站点白名单放开。

**绝不改页面。** 只在 `<body>` 上挂一个 0×0 的 Shadow DOM 宿主，不注册 MutationObserver，不做全页扫描（`__fxph.scan()` 是你手动调用才跑）。样式全部封在 shadow root 里，用 `all: initial` 挡住站点 CSS。

**币种识别是证据加权**（见上面「币种识别」一节）：`¥` 在 `lang=ja` / 假名占比 / 全文「円」/ 邻近日文词 / `.jp` 这些证据下判 JPY，反之判 CNY；无法判断时默认 CNY 但打「猜测」徽章。原始币种下拉一直摆在卡片上，校准一次后按域名记住，同一站点不再犯。

**UI 与逻辑分离，为外包设计留好接口**：所有视觉取值是 16 个 CSS 变量，所有元素带稳定的 `data-part` 属性，设计师的 CSS 通过 `<style id="fxph-theme">` 追加在内置样式之后（同优先级下后者生效，所以不需要 `!important`）；接入口有三个：设置面板的「自定义主题 CSS」文本框、`__fxph.setTheme(css)`、以及 `cfg.themeCss`。DOM 结构与档位契约写在 `THEME.md`。

**汇率**：`open.er-api.com`（免 key，日更，161 币种，含 TWD）→ 失败回落 `api.frankfurter.app`（ECB，无 TWD）→ 再失败用上次缓存并标注 stale → 都没有才用内置离线示例表并标注「不是当前汇率」。30 分钟 TTL；日更数据源下这基本等于一天一次请求。

## 已知限制（先认了，别当 bug 修）

- **跨域 iframe 内的金额识别不到**（`@noframes`），Canvas 画的价钱（票务/地图）也不可能识别 → 覆盖率有天花板。
- `input` / `textarea` / `contenteditable` / `code` / `pre` 内的数字故意不识别（用户正在输入，或不是正文）。
- `$1.000` 按千分位解析成 1000；对 en-US 站点本意可能是 1.00 美元。这类"点作千分位"的争议只能靠站点白名单收敛。
- `$` 默认 USD；`kr`（SEK/NOK/DKK）、`元`（韩元/台币俗称）等未支持。
- **`PHP` / `INR` / `VND` / `BRL` 故意不做裸代码识别**：`PHP 8.2` 在开发者页面上是编程语言而不是菲律宾比索，这几个币种只认符号（`₱` `₹` `₫` `R$`）。
- 空格千分位（`1 299`）已支持，但「`$100 500MB`」这类**空格千分位后紧跟字母**的会整条放弃——宁可不显示，也不能显示成 100500。
- 「元」在台湾站点会判 TWD，但「元」也可能是韩元/港元的俗称，目前只把 TWD 当第二候选；北欧 `kr` 依赖域名（`.se`/`.no`/`.dk`），没有域名证据时只能猜第一个候选。
- 中文数字（`三千元`、`两百块`）不支持，只支持阿拉伯数字 + `万/亿/千/百/k/M`。
- 固定位置小窗不跟随滚动：滚动即关闭（v1 取舍）。

## 量什么指标

按之前的评估，判断"能不能做成真产品"的是这四条：

| 指标 | 目标 | 怎么量 |
| --- | --- | --- |
| 币种识别正确率 | ≥ 95% | 每个站点悬停 20 个金额，人工核对小窗里的币种 |
| **弹错币种率** | ≤ 1% | 同上（这条最致命，尤其 `¥`） |
| 不想看却弹出 | ≤ 3/100 次 | 悬停时数"我没想看它却弹了" |
| 页面开销 | 无持续 CPU | DevTools Performance 录 10 秒，看有没有常驻任务 |

`__fxph.stats.dump().rejects` 的分布能告诉你误判来自哪条规则（"窗口内无金额"/"光标未真正落在金额上"/"无货币标记"…），调参就看它。

## 下一步（要变成扩展时需要改什么）

油猴阶段的两个便利在扩展里会消失，提前记着：

1. **`GM_xmlhttpRequest` 不受 CORS 限制**，扩展的内容脚本不行 → 取汇率要挪回 service worker，缓存放 `chrome.storage.local`，内容脚本只读缓存（顺带好处：小窗永远不发网络请求）。
2. **`@match *://*/*` 在商店里是"读取和更改您在所有网站上的数据"**，而本项目原来的卖点是最小权限。建议改成按站点 opt-in：默认不注入，用户点「在本站启用换算」时才 `chrome.permissions.request` + `chrome.scripting.registerContentScripts`（manifest 里已经有 `optional_host_permissions` 了）。
3. 别往"自动给页面所有金额加下划线"的方向走：性能、样式冲突、站点封杀、商店审核都更糟，而且用户没要求就标错更招人烦。
